## 5. Patched-model fidelity and fused kernels

Nineteen findings (from 21 verified reports, after two merges). This is the heaviest
high-severity cluster in the delta, and it has a single theme: **the performance work in this
milestone caused correctness regressions.** Every high finding below traces to a commit whose
stated purpose was throughput — `c0f95ced` (#988, "activate fused loss-only cross-entropy") flipped
the fused-CE forward wrapper from opt-in to default-on and thereby made a pre-existing wrong
fallback branch reachable at trainer defaults (OPQ-460) while also making `torch_compile` unusable
(OPQ-462); `a839782e` (#987, "reuse fused cross-entropy statistics") broke bare `torch.func.grad`
(OPQ-463); `d80d3f99` (#954) and `4e61b09d` (#925) extended the compact-SDPA mask elision to
gemma2 and reopened OPQ-337 in a sibling path (OPQ-472); the four QKV-fusion commits
`41722a0b` / `414504dc` / `8ced13cf` / `bf2190b9` (#947/#949/#951/#950) built dedicated wrappers for
two families and left six more on a generic wrapper that is not faithful to any of them
(OPQ-465, OPQ-466); `b9fb8674` (#985) added a functorch guard that never fires (OPQ-464). None of
these move ε — clipping and noise still apply to whatever gradient is produced — so the damage is
silent infidelity to the loaded architecture, a different trained objective, or a hard outage.

### 5.1 Fused cross-entropy and fused DFT loss

**OPQ-460 — the fused-CE forward wrapper's non-fused fallback branch recomputes logits without the family's post-`lm_head` transform, so Cohere/Cohere2/Granite/Gemma2 train on a different objective.** `packages/opaque-patches/src/opaque/api/patches/transformers/components/cross_entropy.py:282-292, 356-364` · silent-training-corruption · **high** · ε:no · **CONFIRMED**. *(merges two independently reported instances: "Default-on fused-CE forward wrapper silently drops Cohere logit_scale / Granite logits_scaling / Gemma2 final_logit_softcapping on its non-fused branch", "The fused-CE wrapper's non-fused fallback branch recomputes logits without family logit scaling".)*
- **Claim:** `c0f95ced` (#988) changed the gate at `_factory.py:374-376` from `kwargs.get("fused_linear_cross_entropy", False)` to "inherit from `performance`", and `_dp_trainer.py:844-850` always calls `apply_model_patches(..., performance=True)`, so the fused causal-LM forward wrapper is now installed on all seventeen families in `_FUSED_CE_CAUSAL_LM` (`cross_entropy.py:122-140`) by default. The same commit made the DP training loss set the marker (`_dp_trainer.py:2437-2442` adds `loss_only=True`). The wrapper's fused branch resolves and threads the family transform into the kernels (`cross_entropy.py:308-323, 336`), but when `use_fused_ce` (`:282-292`) is False the wrapper does **not** delegate to `original(...)` — it re-implements stock Llama's tail, `logits = self.lm_head(hidden_states[:, slice_indices, :])` followed by `self.loss_function(logits, labels, self.vocab_size, **kwargs)` (`:356-364`), with no `logit_scale`, no `logits_scaling`, and no `final_logit_softcapping`. In transformers 5.15.1 those transforms live in `ForCausalLM.forward`, not in `loss_function` (`cohere/modeling_cohere.py:503`, `cohere2:481`, `granite/modeling_granite.py:497`, `gemma2:527-530`), so the fallback silently scores a different objective.
- **Failure scenario:** DP-SFT of a Cohere / Cohere2 / Granite / Gemma2 checkpoint loaded in **float32 on CUDA** with the DPTrainer default `bf16=False` (`_training_arguments.py:415`; `_setup_precision` leaves `_amp_dtype=None` and never casts the model, `_dp_trainer.py:904-905`). `use_fused_ce` requires half-precision hidden states on CUDA, so fp32 hidden states take the else branch on every step and every per-example loss *and its gradient* are computed from untransformed logits. No exception, no warning; clipping and noise still apply, so the run looks healthy. Measured on CPU by forcing the identical branch with tiny models: the fused branch matches unpatched HF to 0.0000 % for every family, while the fallback gives Cohere +0.27 % at random init, +53.0 % with `lm_head` scaled 10×, and +602 % at 50×; Granite −0.36 % / +10.0 % / +215 %. The error grows with logit magnitude, so a trained checkpoint is badly wrong rather than marginally. A second, device-independent route exists: a caller (for example a padding-free collator) passing `shift_labels` of shape `[B,T]` reproduces Cohere +53.0 % on CPU. A separate forced-branch run measured max per-logit differences of 0.665 (Cohere, `logit_scale=0.0625`) and 0.344 (Granite, `logits_scaling=8.0`), with Llama and un-softcapped families bit-identical.
- **Evidence:** `cross_entropy.py:356-364` (the un-transformed re-implementation); `:282-292` (the CUDA + fp32 decline); `:151-172` (`_fused_linear_ce_loss_is_supported` also declines for `shift_labels`, class `weight` and tensor `ignore_index`, on any device); `:308-323, 336` (the fused branch does apply the transform); `:204-220` (the wrapper *does* delegate to `original` when `labels is None or not loss_only`, which is why ordinary inference is unaffected); `_factory.py:374-376` plus `git show c0f95ced` for the old `False` default; `_dp_trainer.py:844-850, 866-875, 2437-2442`; `_training_arguments.py:415`; transformers 5.15.1 `cohere:503`, `cohere2:481`, `granite:497`, `gemma2:527-530`; config defaults `CohereConfig.logit_scale=0.0625` and `Gemma2Config.final_logit_softcapping=30.0`.
- **Fix:** make the fallback delegate to `original(self, ...)` — it already has every argument it needs, and the wrapper already does exactly that at `:204-220` and for MoE router logits at `:225-244`. Failing that, hoist the `logit_scale` / `logits_scaling` / `final_logit_softcapping` resolution above `if use_fused_ce:` and apply it to `logits` before calling `self.loss_function`. Lock it in by extending `test_fused_ce_text_family_parity.py` to Cohere, Cohere2, Granite and Gemma2 over **both** branches: its fixtures are currently olmo2/olmo3/smollm3/ministral/glm4 (none of which has logit scaling) and its scaling tests install a `loss_function` that raises `AssertionError("fallback should not run")`, pinning only the fused path.
- **Notes:** not reachable on CPU or MPS, where the chunked fused branch always wins, and not reachable with the transformers 5 `from_pretrained` default `dtype="auto"`, since Cohere/Granite/Gemma2 checkpoints are bf16 and route to the correct fused branch. The trigger is fp32-on-CUDA, a documented first-class mode (`docs/user-guide/precision.md` "float32 training", `examples/train_dpftrl.py --dtype float32`) rather than the most literal default — which is why the first report's "critical" was reduced to high. One sub-claim was cut: the returned `output.logits` are *not* corrupted for any consumer, because the fallback only runs on calls that set `loss_only=True` and every in-repo caller sets that marker exactly when discarding logits. Gemma3 is largely spared in practice (`Gemma3TextConfig` defaults softcapping to `None`), and stock `GraniteConfig` defaults `logits_scaling=1.0`, so Granite bites only on real checkpoints that set it above 1.

**OPQ-461 — SFT loss-only DFT evaluation scores an unscaled-logit objective, so the same checkpoint reports two different `eval_loss` values depending only on whether `compute_metrics` is set.** `packages/opaque-transformers/src/opaque/api/transformers/trl/_sft_trainer.py:230-236, 596-605, 666-670`; root cause `packages/opaque-alignment/src/opaque/api/alignment/sft/loss/_dft.py:141-147` and `packages/opaque-alignment/src/opaque/api/alignment/_fused_lce.py:107-122` · correctness/objective-divergence · **high** · ε:no · **CONFIRMED**.

But `prediction_step` requests the no-logits closure whenever `prediction_loss_only` is set (`:666-670`), and `DPTrainer.evaluate()` sets `prediction_loss_only=True` whenever `compute_metrics is None` (`_dp_trainer.py:3187`). `fused_dft_loss` has no scale argument at all: its CUDA/chunked branch calls `linear_nll_sum(...)`, which pins `logit_scale=1.0` (`_fused_lce.py:113-114, 120-122`), and its eager fallback is `dft_loss(hidden_states @ lm_head_weight.transpose(-2, -1), labels)` (`_dft.py:147`). Neither applies `config.logit_scale` nor `config.logits_scaling` — the exact sibling that the `c0f95ced` logit-scale work fixed for the model-level fused CE and did not fix for the DFT primitive.
- **Failure scenario:** `SFTTrainer(model=<Cohere | Cohere2 | Granite with logits_scaling != 1>, args=SFTConfig(loss_type="dft", ...))`. Whenever evaluation runs without `compute_metrics`, `eval_loss` measures DFT against the raw `hidden @ lm_head.T` projection. Measured on this tree with the repo's own DFT trainer fixture and a tiny Cohere: `eval_loss = 0.060834` without `compute_metrics` versus `0.064736` with it — and `0.064736` is also the training objective, so the divergence is 6.0 %. `metric_for_best_model="eval_loss"` and early stopping therefore select on the wrong objective. Primitive-level per-example measurements: Llama 0.000 %, Cohere (`logit_scale=0.0625`) 0.610 %, Granite (`logits_scaling=8.0`) 2.085 %, Granite (1.0) 0.000 %. Llama is unaffected, which is exactly why the existing consistency test passes. Same root cause, worse consequence: with `log_completion_metrics=False`, `_fused_dft` becomes True (verified by direct construction) and the unscaled DFT loss becomes the **training** objective for these families, silently.
- **Evidence:** `_sft_trainer.py:216-220` (`_fused_loss_eligible` requires `not self._log_completion_metrics`) against `_sft_config.py:90` (`log_completion_metrics: bool = True`); `_sft_trainer.py:233-235, 596, 604, 606-615, 666-670`; `_dp_trainer.py:3187`; `_dft.py:141-147`; `_fused_lce.py:113-114`; contrast `cross_entropy.py:308-320, 336`, where the model-level path does thread the scale; transformers 5.15.1 Cohere `logits = logits * self.logit_scale` and Granite `logits = logits / self.config.logits_scaling`; `test_trl_trainers.py:2030-2037` is `test_sft_dft_eval_loss_consistent_across_metric_modes`, the test that exists to catch precisely this and passes only because `_dft_trainer` uses `_tiny_model()` = `LlamaForCausalLM` (`:41-51`); grep confirms no logit-scale plumbing exists anywhere in `opaque-alignment`.
- **Fix:** thread the family scale into the DFT primitive the way `c0f95ced` did for the model-level fused CE — give `linear_nll_sum` a `logit_scale` parameter (it already forwards positionally into kernels that accept one) and give `fused_dft_loss` `logit_scale` / `logit_softcapping` arguments applied in both the fused and the eager `hidden @ W.T` fallback, with `SFTTrainer.compute_per_example_loss` reading them off `self._model.config`. Until that lands, gate `_fused_dft` and `_fused_dft_loss_only` on the model having no logit scaling so a scaled family keeps the eager logits path. Re-parametrize `test_sft_dft_eval_loss_consistent_across_metric_modes` over a logit-scaled family, not just Llama.
- **Notes:** needs the opt-in `loss_type="dft"` (`SFTConfig` defaults to `"nll"`, `_sft_config.py:80`) plus a logit-scaled family; no privacy guarantee is involved. Distinct from open issues #905/#906 (wandb metric naming) and #862 (fp32 logit upcasting).

**OPQ-463 — the multi-output `apply` override added by #987 breaks bare `torch.func.grad` for both linear-CE kernels, disabling `opaque.auditing.gradient_scores`.** `packages/opaque-patches/src/opaque/api/patches/kernels/_linear_ce_chunked.py:278-281, 330`; same pattern at `kernels/linear_cross_entropy.py:1005-1008, 1061` · regression · **medium** · ε:no · **CONFIRMED**.

### 5.2 Fused LoRA QKV and MLP wrappers
